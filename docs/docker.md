
- restart: always
	OSを起動したら自動でコンテナが立ち上がるようにする設定
	デフォルトはno。on-failureはエラー終了のときだけ、unless-stoppedはOSを終了したときの状態にする

Dockerは使用したいアプリとそれが依存する環境を「コンテナ」としてひとまとめにして、それを複数管理できるようにするツールです。
アプリケーションごとに環境やボリュームを作るので、それらを他のアプリケーションに影響することなく、簡単に削除したり再作成することができます。またDockerHubを通じて世界中の開発者と同じ構成を共有することもできます。
ホストシステムのLinuxカーネルのnamespacesとcgroupsという機能を使用して、ホストOSのカーネルを共有しながらプロセスごとに環境を管理することができます。この仕組みにより、非常に軽量に複数の環境を立ち上げることができます。
それに対してVMは、物理的なハードウェア(CPU・メモリ・ストレージ)を仮想的に作り、完全なOSを立ち上げて、その上で使用したいアプリを起動します。そのため異なるOS上でのGUIアプリの動作確認をしたい場合や、古いOSでしか動かないレガシーアプリの起動、またセキュリティ性に優れているので環境を完全に分離する必要がある場合などに用いることができます。ゲストOSごとにアップデートやセキュリティ管理が必要で運用コストがかかってしまいます。
カーネル...OSの中核を担う、アプリケーションの実行を許可し、プロセス管理、安全なメモリへのアクセス管理、コンピュータに接続された周辺機器のデバイス管理を行うソフトウェア
namespaces...プロセスIDやネットワーク、ファイルシステムを“別室”から見えるように偽装
cgroups...CPUやメモリを「この部屋は1コアまで」「この部屋は512MBまで」と決める仕組み
